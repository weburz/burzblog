# BurzBlog

One Go binary (`cmd/burzblog`) is the server, the embedded browser panel and the
terminal client. Posts are Markdown stored in one SQLite file. Read
`docs/adr/013-database-storage.md` and `docs/security.md` before changing
storage, auth or the API. ADR-001 to ADR-012 are superseded history.

- `task setup`: Go modules, pnpm dependencies, the Playwright browser.
- `task dev`: Go API on :8080 (data in ./burzblog-data) and Nuxt dev on :3000.
- `task build`: panel build, `scripts/embed-panel.sh`, then `bin/burzblog`.
- `task check`: `go:check` (gofmt, vet, `go test -race`), `web:check` (oxfmt,
  oxlint, types, Vitest, build, Playwright E2E) and pre-commit hooks.
- `task docker:check`: Hadolint, proxy examples, image build, `scripts/docker-smoke.sh`.
  Run it where Docker exists; otherwise report it as unrun.
- `task format`: gofmt and oxfmt. Make targets are compatibility aliases.

Layout: `internal/post` (model, validation, frontmatter; no IO), `internal/store`
(SQLite, migrations in order, never edit a shipped migration), `internal/auth`,
`internal/render` (goldmark + bluemonday), `internal/server` (HTTP), `internal/client`
and `internal/cli`. `internal/panel/dist` is generated by `embed-panel.sh`;
never commit or hand-edit it.

- Every change to a post goes through `store.UpdatePost` with the version the
  caller started from: no silent overwrites, previous content kept as a revision.
- Never add an unauthenticated content route. Browser changes need Origin + CSRF;
  export tokens may only call the export.
- Frontmatter keys BurzBlog does not model must round-trip unchanged (`extra`).
- The deploy hook URL is secret: never return or log it.
- Go: Google style, explicit errors with actionable messages, standard `testing`
  with positive and negative cases, tests in temp directories. Panel: Nuxt UI,
  arrow functions, Vitest + Playwright. Keep Playwright at 1.61.1 until its
  Chromium 151+ headless regression on WSL2 is resolved.
- Browser E2E builds the real binary and runs it on 127.0.0.1:3000 with a
  disposable data directory; never point tests at real content.
- Short-lived feature branches; commit via Crisp; never push to main directly.
  GitHub Actions is intentionally disabled: run `task check` and record exact
  results in PRs. Keep the dormant workflows reproducible.
- Docker: content and secrets stay outside the image; preserve host UID/GID.
- The license is Apache-2.0 (`LICENSE`); keep it. The `admin-panel/` cache is
  unrelated and must not be incorporated.
